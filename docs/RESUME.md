# 简历条目重写建议（pai-next 对照旧 MyCLI 四条）

> 旧简历四条的主题：① 统一 agent 循环与工具治理；② DAG 任务编排（Planner/Worker/Reviewer、验证、资源冲突）；③ 记忆检索与上下文压缩；④ MCP 接入。下面给每条"保留什么 / 换什么 / 新措辞 / 可写的数字 / 面试口径"。原文逐句对照版等拿到原文再做。

## 总体口径

- 项目名用 **pai-next**（或 "PaiCLI 2.0"），一句定位：*Java 21 终端 coding agent，极小内核 + 扩展 SPI，架构对标 pi*。
- 旧第 ② 条的 DAG **整条拿掉**，换成"任务清单 + 验证钩子 + 子代理"。如果面试官拿着旧简历问 DAG：**"一代做过 DAG 编排，二代有意拆掉了，原因是……"**（见 INTERVIEW.md §2）。这比硬守旧说法好得多。
- 旧第 ③ 条的"检索"换成"文件记忆 + 压缩→记忆候选"，"压缩"保留并加强。
- 数字只写仓库里能查到的；每个数字对应一个报告或脚本。

## 条目一：内核与工具治理（保留，更强）

**新措辞**
> 设计并实现 provider 中立的 agent 内核（约 5k 行，行数预算与 ArchUnit 强制）：sealed 消息类型统一 OpenAI/Anthropic 两种 wire format 与 thinking 签名回放；事件驱动的 agent loop，每轮固定管线（钩子链 → 上下文阶段 → provider → 工具 → 终止判定），7 种终止原因可观测；工具契约 `effect/effect(input)/concurrencySafe(input)` 驱动并行分组与审批，bash 经词法解析 + 只读表按输入判定效果等级（95 条表驱动样例，含 glob/引号/替换绕过）。

**可写数字**：core 5249 行 / 预算 5500；11 模块 18.8k 行；874 测试；一次工具调用 loop 开销 1.63 ms。
**面试口径**：讲 ADR 0001–0003 和 `effect(input)` 的 fail-closed 规则；主动讲 glob 注入那个 P0。

## 条目二：编排（整条替换）

**新措辞**
> 以"编排在模型、框架只提供薄机制"替代一代的 DAG Planner/Worker/Reviewer：任务清单工具（状态持久化到 session、注入 system prompt）、验证钩子（写文件后自动编译/测试，失败输出回灌模型自修，写构建脚本时跳过防提权）、PLAN 只读模式、子代理（`spawn_agent`，explore/reviewer 类型只读过滤，侧链 transcript 使父上下文不含子代理读过的文件正文，父取消传递，子代理间按真实路径写锁）。

**可写数字**：子代理 explore 在 9 文件陌生仓库找全 4 处调用点，父 session 0 泄漏；并发 ≤4。
**面试口径**："为什么拿掉 DAG"是必问，答案在 INTERVIEW.md §2；说清旧 DAG 每个职责的新归属。

## 条目三：上下文与记忆（半换半强）

**新措辞**
> 三层上下文管理：确定性微压缩（请求投影，不写 session，两档 + 滞回）、六节结构化摘要（校验缺节/漏文件则重试，否则不压缩，连续失败熔断）、压缩后按 `Files touched` 回灌文件当前内容使模型不必重读即可编辑；8k 窗口同一任务全量压缩 4 次 → 0 次。记忆改为可手编的 MEMORY.md + 主题文件，会话开始固定注入不破 prompt cache，压缩摘要的 Decisions 节经用户逐条确认进入记忆，拒绝持久化。

**可写数字**：压缩 4 → 0 次；全量摘要 40382 → 2085 token；微压缩 200 条 0.13 ms；注入上限 60 行/4000 字。
**面试口径**：旧简历若写了"检索/向量/RRF"，直接说二代放弃了检索式，理由：量级小、破缓存、模型压缩时已判断过什么值得留。讲两个 token 估算的坑（重复扣除、stale usage）会很加分。

## 条目四：MCP 与扩展 SPI（保留，加 SPI）

**新措辞**
> 扩展 SPI（有限枚举钩子、能力方法式 `ExtensionContext`、classpath 优先于 drop-in jar、项目 jar 需信任），审批/记忆/MCP/任务/验证/子代理全部为扩展且互不依赖（ArchUnit）；独立 MCP 客户端支持 stdio 与 Streamable HTTP，MCP 工具实现同一 Tool 接口、效果等级 UNKNOWN 在只读模式下 fail-closed；SPI 共 4 次修订，每次由实施阻塞 → 报告 → ADR 修订驱动，拒绝绕法。

**面试口径**：讲 `subLoop` 为什么只转发两个钩子；讲"拒绝 cli 直接依赖 ext"的理由。

## 可以单列的一条：工程方法（如果简历有"工程实践"栏）

> 规格驱动 + 独立审查：每阶段规格书定公开签名为合同；实施与审查分离，审查不读实施报告、实验写明参数可复现；约 125 条裁决只追加记录，5 个 ADR 共 12 条修订；审查在 8 个阶段抓到约 30 个真 bug（含 3 个默认配置下免审执行任意代码级别），全部有测试守护；CI 跨 Linux/Windows + gitleaks。

- 没验证过的 Anthropic live、平台沙箱、向量检索。
- 具体行数以外的"性能提升 X%"——我们只有基线没有对比（除压缩次数 4 → 0）。
