# M7.5 规格书：子代理（上下文隔离、只读 explore、写冲突预检）

> 前置：M7 通过（依赖 7B 的 `Tool.effect(input)`，explore 类型据此过滤工具）。原 M5 §5B 的子代理条目整体迁至本文件，M5 不再包含它。
> 定位：补齐"没有 DAG 如何编排"的第三件实物（任务清单、验证钩子之外）。预计 400–600 行主代码，一个扩展模块 `pai-ext-subagent`，core 零改动为预期。
> 机制对照 Claude Code Task 工具与 Codex `spawn_agent`（公开解读，机制层面）。

## 工具与类型

```java
public final class SubagentExtension implements Extension { id()="subagent"; }
// spawn_agent(task: string, agentType?: string = "general", background?: boolean = false)
//   effect=EXECUTE, concurrencySafe=true（多个 spawn 可并行）
//   返回：子代理最终 assistant 文本 + runId + usage 摘要；background=true 时立即返回 runId
// agent_result(runId)  READ_ONLY —— 取后台结果（未完成返回 running）
// agent_cancel(runId)  READ_ONLY
public record AgentType(String name, String description, String systemPromptAddendum,
                        Set<String> allowedTools, boolean projectContext, Optional<String> model) {}
```

预置类型（资源文件），用户可在 `~/.pai/agents/*.md` 追加（frontmatter：`name/description/tools/model/project-context`，正文为提示词；格式对齐 Claude Code 的 `.claude/agents/`）：

| 类型 | 工具 | 项目上下文 | 用途 |
|---|---|---|---|
| `general` | 父的全部工具（除 spawn_agent） | 是 | 独立子任务 |
| `explore` | 仅 `effect(input)==READ_ONLY` 的调用会被放行（read/grep/glob/bash 只读形态）；写/执行在 beforeToolCall 被拦 | **否**（不注入 PAI.md、记忆、skill 索引——省 token，Claude Code Explore 同做法） | "在仓库里找 X" |
| `reviewer` | 同 explore + 固定审查提示词，输出结构化问题列表（文件:行号、严重度、建议） | 否 | 代码审查 |

## 隔离与生命周期

- 同进程新建 `AgentLoop`；**子 session 为侧链文件** `sessions/<cwd-hash>/subagents/<parentSessionId>/<runId>.jsonl`（header `parentSession` 指回父）；父 session 只追加一条 `CustomEntry{subagent: runId, type, task, resultSummary(≤500 字), usage}`。父上下文**不含**子代理读过的任何文件内容——这是验收项。
- 父只收最终 assistant 文本；子代理 `maxTurns` 独立（默认 30）；**禁止嵌套**（子代理工具集里没有 spawn_agent）；并发上限默认 4（`option("subagent.max-concurrency")`）。
- hooks 链复用父的（审批照常：子代理的 write/bash 仍要父会话的审批 UI，串行化已有锁）；`explore/reviewer` 的工具过滤由本扩展的 `beforeToolCall` 按 `tool.effect(input)` 实现，不依赖 ext-hitl。
- abort 树：父 `CancelToken` 取消 → 全部子取消；子失败不影响兄弟，错误以文本返回父。
- 事件：子代理 `AgentEvent` 以 `ToolExecutionUpdate(partial)` 向父汇总（每 turn 一行摘要）；TUI 折叠；`PAI_DEBUG_SUBAGENT=1` 全量透传。

## 写冲突预检（旧 DAG 唯一保留的调度思想）

- 多个后台子代理并发时，`WRITE_FS` 调用在执行前按 **`PathGuard.real`（M7 后下沉到 pai-tools 的路径解析）** 得到真实路径，取 per-path `ReentrantLock`；后者等待（带超时 60s → 失败文本），不是覆盖也不是失败。
- 预检只针对 `path` 参数的工具；bash 不预检（与 PathGuard 范围一致，文档写明）。

## 不做
子代理间通信、团队/角色协商、后台任务队列持久化、远程执行、Reviewer 作为强制门禁。

## 测试
- explore 类型：write/bash 非只读形态被拦，read/grep 放行；不注入项目上下文（请求体断言）。
- 父 session 不含子代理读到的文件内容；`CustomEntry{subagent}` 字段齐全；侧链文件存在且 header 指回父。
- 禁止嵌套；并发上限；父取消传递；子失败隔离。
- 两个后台子代理写同一真实路径（含 symlink 指向同一文件）→ 串行；不同路径并行。
- `~/.pai/agents/*.md` 解析与覆盖预置。
