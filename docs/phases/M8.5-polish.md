# M8.5 规格书：日常可用性小修（prompt 指引、Python verify、子代理进度、敏感文件只读拦截）

> 前置：M8 通过（tag M8）。四个小项，合计预计 ≤ 250 行主代码，全部在扩展与 tui；core 零改动；cli 零改动（1998/2000 封顶）。目的：把评测与记录里"直接影响日常使用"的小缺陷修掉，然后由用户自己使用一周收集下一批问题。

## 8.5A 扩展指引（让模型真的用扩展）
- 背景：M8 评测 60 次运行中 todo/spawn_agent/load_skill/remember 调用均为 0。各扩展 `prepareRequest` 注入的指引过弱。
- 改动（只改各扩展注入的 system prompt 段，不改 core 基础 prompt）：
  - ext-tasks：`<tasks>` 指引改为明确规则："涉及 ≥3 个步骤或 ≥2 个文件的任务，先用 todo_write 列出清单再动手；每完成一项立即更新；同一时间只有一项 in_progress"。清单为空时也注入这条规则（现在仅非空时注入——确认并改）。
  - ext-subagent：注入一段："在不熟悉的仓库里定位代码、找调用点、理解结构时，用 spawn_agent(explore) 而不是自己逐个 read；审查自己的大改动时可用 reviewer"。注意 PLAN 下可派 explore。
  - skills：索引段末尾加一句"当任务与某个 skill 的描述匹配时先 load_skill 再动手"。
  - 总增量 ≤ 400 字，不得破坏 prompt cache（会话内固定）。
- 验证：**live（DeepSeek）**三道任务，每道各跑一次改前/改后：(1) 在 pai-next 自身仓库"找出所有调用 `Tool.effectOf` 的位置并说明用途"→ 改后应出现 spawn_agent(explore)；(2) "给 pai-ext-tasks 加一个 `/todo stats` 命令，打印各状态计数，并加测试"（≥2 文件）→ 改后应出现 todo_write；(3) 一个与现有 skill 匹配的任务（看 `~/.pai/skills` 或仓库 skills 里有什么，没有就临时放一个）→ load_skill。报告附改前/改后的工具调用名序列。不要为了"命中"去改任务描述。

## 8.5B verify 的 Python 默认规则
- 无 `.pai/verify.json` 时，检测到 `pyproject.toml` / `setup.py` / `setup.cfg` / `requirements.txt` 任一 → 规则 `{"on":"write|edit","pathGlob":"**/*.py","run":"python -m compileall -q <changed-file>","timeoutSeconds":30}`——注意现有规则是整仓命令；这里要支持 `<changed-file>` 占位（或 `{path}`），只编译本次改的文件。`python` 不存在时回退 `python3`，都不存在则 notify 一次并跳过（不报错）。
- 与 M5 的"写构建文件跳过自动运行"规则一致：`pyproject.toml`/`setup.py`/`setup.cfg` 加入构建定义文件清单。
- 测试：规则探测、占位替换、语法错误回灌文本、python 缺失跳过。GLOSSARY/HANDOFF 不改；`docs/reports` 可写。

## 8.5C TUI 渲染子代理进度
- `EventView` 处理 `ToolExecutionUpdate`：对 `spawn_agent` 的 partial 更新，在状态行下方以一行折叠显示 `[sub-agent sa-xxxx] turn N: <摘要 ≤ 80 字>`，同一 run 覆盖上一行（不滚屏）；run 结束时一行 `[sub-agent sa-xxxx] done (N turns)`。Plain renderer 下每条 update 打印一行（可被 `--quiet` 抑制）。
- 其他工具的 `ToolExecutionUpdate` 维持现状（不显示）。
- 测试：tui 用 fake renderer 断言覆盖与结束行；不改 tui 之外。tui 预算 1500（现 1008）。

## 8.5D 敏感文件进入只读免审判定
- 背景：AUTO_READ 下 `cat .env` 属只读命令免审；`read .env` 工具同样免审（PathGuard 只管 cwd 内外）。
- 改动（ext-hitl）：只读免审前检查路径/参数词是否匹配敏感文件名表（与 M7 `FileRestorer` 排除表一致：`.env*`、`*.pem`、`*.key`、`*.p12`、`*.jks`、`*.pfx`、`*.keystore`、`id_*`、`*credential*`、`*secret*`、`.npmrc`、`.netrc`、`.pgpass`、`*.kdbx`）→ 转审批（不是 block，用户可批），提示标明"sensitive file"。对 `read`/`glob`（返回内容的）和只读 bash 的每个路径词都检查；表做成 hitl 资源文件 `sensitive-files.txt`，M7 的 `FileRestorer` 改为读同一张表（**cli 零改动的前提下**：若 FileRestorer 在 cli 且读表需要改 cli 一行，则把表放 pai-core 资源由两处读；core 只加资源文件不加代码）。
- YOLO 不受影响；PLAN 同 AUTO_READ。
- 测试：`cat .env` 转审批、`read .env` 转审批、`cat README.md` 免审、大小写不敏感、路径在子目录（`config/.env.local`）。
